# PC 图形界面方案

## 目标

host 使用 M5Stack Tab5 的布局和素材，让共用 UI 可以在电脑上开发、调试。GUI 版有和固件相同的菜单，可以载入 GB ROM，用解释器运行，显示游戏画面和游戏页的指标，播放声音，接收键盘输入。保留无窗口方式，供不需要显示的开发和自动化检查使用。

PC 版仍然只有解释器，不包含 RISC-V JIT，也不代替板上测试。整体定位见[架构](architecture.md)。

## 技术选型

采用 LVGL 9 + SDL3。LVGL 继续负责界面，复用固件的页面、控件逻辑和资源包，不另外维护一套桌面版 Tab5 UI。SDL3 负责桌面窗口、输入，以及画面的缩放、合成和显示。

LVGL 在 CPU 上软件绘制 UI，SDL3 的 `SDL_Renderer` 2D 接口完成最终显示。游戏画面作为独立纹理参与合成，不经过 LVGL，所以游戏画面刷新时不必重画外壳。项目不直接维护 Metal、Vulkan 或 OpenGL 代码，后端由 SDL 按平台和运行环境选择。暂不引入需要自行管理渲染管线的 `SDL_GPU`，自定义 shader 和后处理等有需求时再评估。

相关说明见 SDL 的[渲染器文档](https://wiki.libsdl.org/SDL3/SDL_CreateRenderer)、[驱动选择说明](https://wiki.libsdl.org/SDL3/SDL_HINT_RENDER_DRIVER)和 [GPU 接口文档](https://wiki.libsdl.org/SDL3/CategoryGPU)。

## 界面与范围

面向 macOS 和 Windows，复用游戏页、控件反馈和菜单。GUI 版可以从菜单的 ROMS 选游戏，也可以通过命令行载入 GB 或 GBA 的 ROM。GBA 游戏还没有声音，卡带存档不写回，也不能即时存档。手柄尚未接入。菜单的画法和操作见[界面布局](ui-layouts/index.md#菜单)。设置里 PC 不支持的项显示为灰色，比如 BRIGHTNESS，以及只有解释器可选的 CPU。

沿用 Tab5 的 720×1280 布局，窗口固定为 9:16，允许等比例缩放，不为桌面重新排版。鼠标模拟单个触点，复用共用 UI 的命中逻辑。游戏画面按放得下的最大整数倍放大，居中放在资源包指定的游戏窗口里。`SCALING` 的两种模式和固件相同，默认是 `SMOOTH`。

鼠标按住屏幕上的控件时，和板子上的触摸一样向 GB 传递按键，和键盘的按键合在一起。速度开关没有接入模拟节奏。VFD 显示和固件相同的指标，PC 取不到的片内内存、PSRAM 和核的空闲比例显示 `N/A`。

主界面不引入 Qt 或 Dear ImGui。以后如果需要寄存器、反汇编、内存查看器等桌面调试工具，再单独考虑调试面板。

## 运行结构

host 在主线程中处理 SDL 事件、更新 app、运行 LVGL，并上传纹理和呈现画面，SDL 纹理只由主线程使用。

载入 ROM 以后，和固件一样由 app 的 `Game` 运行，见[架构](architecture.md#运行游戏)：模拟线程独占 `gb::System`，PPU 和混音器在另一个线程上处理扫描线和声音任务，音频线程把 PCM 交给 SDL3 的音频流。PC 上这些线程不绑定核，也不设优先级。节奏和固件相同，按音频队列的水位运行；没有可用的音频设备时，按墙钟的帧周期运行。GBA 游戏由 `gba::System` 运行，PPU 在另一个线程上渲染扫描线，因为没有声音，节奏按墙钟的帧周期。宿主运行不及时时游戏会变慢，不跳过 CPU 指令或设备事件。主线程只上传最新的一帧，不积压等待显示的旧帧。

卡的根目录是当前目录：菜单从 `roms/` 列出游戏，存档写在 `saves/` 和 `states/`，设置写在 `config/pc.ini`，格式和固件相同，见[产品设计](product-design.md#sd-卡目录)。命令行给的路径按原样打开。

键盘和鼠标的按键在每次运行一帧前提交给系统，两次采样之间的短按会保留到下一帧，窗口失去焦点、隐藏或最小化时释放按键。退出时先停止模拟和音频线程，再释放 UI 和 SDL 资源。

## 使用与键盘

程序接受一个可选的 ROM 路径。以下命令从仓库根目录运行，路径中有空格时加引号：

```sh
build/host-debug/bin/Debug/gbx path/to/game.gb
```

不传路径时进入主界面，`--help` 显示用法和按键。GBA 游戏要读 BIOS，默认是 `bios/gba_bios.bin`，`--bios <文件>` 可以换成别的文件；`--rom-cache <KiB>` 设定 ROM 分页缓存的大小，范围是 64 至 32768，默认 32768，所以默认整个 ROM 都在缓存里。命令行给的 ROM 无法读取、格式不受支持或初始化失败时，程序输出错误并以非零状态退出。

`roms/` 下的 ROM 的存档照搬它的目录结构，其他位置的 ROM 只用文件名，比如 `path/to/game.gb` 的卡带存档是 `saves/game.0.sav` 和 `saves/game.1.sav`，第 1 个即时存档槽位是 `states/game.1.state`。

运行中解释器返回不可继续执行的错误时，模拟线程停止，暂停菜单打开在最后一帧上，原因记进 ERRORS 列表，控制台记录出错时的 PC。如果这个游戏是命令行给的，用户关闭窗口后程序以非零状态退出。

Windows 命令行参数尚未转换为 UTF-8，含非 ASCII 字符的 ROM 路径可能无法正确打开。

| 键盘 | 按键 |
|---|---|
| 方向键 | 十字键 |
| Z | A |
| X | B |
| Enter | Start |
| 右 Shift | Select |
| A | L |
| S | R |
| Esc | MENU |

映射使用按键的物理位置。GBA 游戏里 A、S 是 GBA 的 L 和 R 键，GB 游戏里它们只给菜单用；MENU 只给菜单用。菜单里方向键移动光标，Z 和 Enter 确认，X 返回，A、S 翻页，Esc 在游戏中打开暂停菜单，在暂停菜单里回到游戏。鼠标在游戏窗口里操作菜单，和板子上的触摸一样。关闭窗口退出程序。

## 构建与资源

默认构建 GUI 版，也提供不依赖 SDL3 和 LVGL 的无窗口构建。GUI 构建由 CMake 下载固定版本的图形依赖并编译，LVGL 与固件使用相同的上游版本，并复用现有工具生成 Tab5 资源包，作为外部文件随程序提供。依赖版本和打包配置见 `host/cmake/Gui.cmake`，构建方式见[架构](architecture.md#构建)。
