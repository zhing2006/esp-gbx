# 任务 1-3：确认传输方案

依据[任务 1-2](task-1-2.md)已经跑通的测试通路和运行报告，确认后续是否沿用现有批量执行格式和传输口，以及是否需要重传或断点续跑。这个任务依赖 1-2，不再安排测试通路的专项耗时测量。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 真机测试计划的“共用的二进制传输”“运行 SM83 单步用例”两节，以及 1-2 的运行报告。
- 各板子文档中的 USB 和串口说明。
- `tests/protocol/execution.h` 中的执行格式，以及现有 runner 和板端执行代码。

## 范围

- 核对现有消息格式、批次大小和 SD 数据读取方式，依据已有验证结果确认是否需要调整。
- 确认是否沿用 Sila P4 上已经验证的 CH340、460800 baud 链路，以及是否需要重传或断点续跑。
- 日常和全量测试使用板上判定。只有需要进一步排查失败用例时，才使用诊断模式，不要求全量诊断运行。

## 不做

- 分阶段计时插桩、重复的全量耗时测量，以及 debug/release 性能对比。1-2 已有的耗时记录保留在运行报告中。
- 固定回归名单。候选大多是整机 ROM，等里程碑 2 接入 ROM 测试以后再定。
- 改动量大的方案，比如换成 USB 高速口或者实现重传。这类方案和用户确认以后另开任务。

## 约束

- 没有具体问题或新需求时，不为了优化而调整已经跑通的协议。
- 不把尚未验证的配置写成已验证，也不把已有总耗时当成某个阶段是瓶颈的证据。

## 完成标准

- 传输方案的结论写进真机测试计划和架构文档，对应的待定项有了结论，或者有了经过用户确认的后续任务。
- 如果改了消息格式或批次大小，重新跑一遍全部单步用例，仍然全部通过。没有改动执行通路时，不为本任务重复全量测试。

## 收尾

- 满足全部完成标准以后，在[任务状态](status.md)里把这个任务标为“已完成”。
- 向用户汇报保留或调整了哪些方案，以及还有什么没有决定。

## 结论

沿用 1-2 已经验证的传输方案，现有消息格式、批次大小、传输窗口和 SD 数据读取方式保持不变。Sila P4 继续使用 CH340、460800 baud，不增加自动重传或断点续跑。使用范围和错误处理约定见[真机测试计划](../../hardware-testing.md#共用的二进制传输)。
