# 任务 2-2：中断、定时器和 CPU 周边

在 2-1 的框架上实现中断、HALT、STOP、定时器、按键和串口。解释器和 JIT 同时实现，用 2-1 的测试通路在板上验收。这个任务依赖 2-1。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- `refs/docs/pandocs/src/` 中的 `Interrupts.md`、`Interrupt_Sources.md`、`halt.md`、`Reducing_Power_Consumption.md`、`Timer_and_Divider_Registers.md`、`Timer_Obscure_Behaviour.md`、`Joypad_Input.md` 和 `Serial_Data_Transfer_(Link_Cable).md`，逐周期的时序看 `refs/docs/gbctr.pdf`。
- mooneye 的[套件说明](../../../refs/tests/game-boy-test-roms/mooneye-test-suite/game-boy-test-roms-howto.md)，以及 `acceptance` 下与 CPU 指令时序、中断、HALT、定时器、串口和开机状态有关的用例。
- 2-1 的调度器、内存映射、系统接口、JIT 块和测试索引。

## 范围

- 中断的请求、分派时序和 EI 的延迟，HALT 的各条路径和 HALT bug，STOP 和按键唤醒，以及执行非法操作码以后的锁死。
- TIMA、TMA 和 TAC 的计时、溢出中断，以及 DIV 与定时器、HALT、STOP 和串口的交互，包括 Pan Docs “Timer Obscure Behaviour”一节描述的行为。正常运行时的 DIV 计数、读取和写入清零由 2-1 实现。
- 按键寄存器和按键中断。
- 串口只实现内部时钟、没有对端的情况，包括传输时钟和 DIV 的对齐。发出的字节通过系统接口交给调用者，测试报告记录串口输出。
- JIT 的块在中断可能被分派的指令边界上退出，比如 IE、IF 或 IME 发生变化以后。中断分派和 HALT 期间的等待由两个后端共用的系统代码处理，不算回退。
- 测试索引中只依赖这些功能的 ROM 改为已支持。

## 不做

- MBC 和 OAM DMA，这些在 2-3；PPU 的 STAT 中断在 2-4。
- 串口的外部时钟和联机。

## 约束

- 定时器和串口按 2-1 的方式用事件和追赶实现，不逐个周期推进。
- 中断请求要在原机上 CPU 看到它的那个指令边界生效，JIT 的块不能跨过这个边界。
- 回退、测试时间和回传大小沿用 2-1 的规则。

## 由你决定

JIT 在块里检查中断的方式、定时器和串口的事件安排，以及 HALT 期间推进时间的方式。

## 完成标准

- 按[双后端优化要求](../../hardware-testing.md#每个任务的双后端优化)，分别优化解释器和 JIT 的中断检查、等待与设备同步路径，提交两边各自的优化前后数据和剩余瓶颈。完成优化并清理临时计时后，再做最终验证。
- 在 Sila P4 上，测试索引中属于 CPU 指令时序、中断、HALT、定时器、串口和开机状态这几个模块、并且不依赖 2-3、2-4 设备的 mooneye 用例，在两个后端上通过，结果一致，回退清单为空或者已经和用户确认。之前通过且受本任务影响的 ROM 仍然通过。
- `run_jit.py` 的检查覆盖块内触发的中断，在板上全部通过。
- 实际改动影响 CPU 执行时，按[真机测试计划](../../hardware-testing.md#选择本次运行的测试)选择受影响的 SM83 操作码组，两个后端都通过。只有通用路径的影响无法缩小时才跑全量，不因任务收尾自动跑全量。
- 报告给出这些 ROM 的速度。按实测速度估算的全量耗时仍在路线图的预算以内；超出时先和用户确认优化方案。
- 另外两块板子的正式固件和测试固件都还能构建。
