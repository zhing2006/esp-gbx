# 任务 1-2：单步测试通路

打通 SM83 单步用例在板子上的整条测试链路：runner 选出用例、发送运行清单，测试固件从 SD 卡读取用例，用 1-1 的解释器执行，按所选模式判定并分批回传结果，最后由 runner 保存报告。1-5 的 JIT 结果和里程碑 2 的整机 ROM 测试以后也走这条链路。这个任务依赖 1-1。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- [真机测试计划](../../hardware-testing.md)全文。这个任务要实现的是其中“选择本次运行的测试”“执行和结果传输”和“通过判据”里单步用例的部分。
- 现有的传输层：`tests/protocol/frame.h`、`tests/device/transport.h` 和 `tests/runner/transport.py`。握手、分批发送和确认都已经实现，并且在 Sila P4 上验证过，直接用它们，不要另写串口代码。
- `tools/prepare_gb_tests.py` 开头说明的 `cases.bin` 布局，以及 `refs/tests/sm83/README.MD` 的判定方法。
- [调试设计](../../debug-design.md)“模拟状态和正确性调试”一节的最后两段：出错时报告第一处差异，缺少 JIT 结果时显示 `NOT RUN`。

## 范围

- 定义执行请求和结果记录的格式，放在 `tests/protocol/` 下，板子和 runner 两边各实现一份。日常和全量测试默认在板上判定，每条用例返回状态，失败时附带实际结果。需要进一步排查失败用例时，诊断模式返回所选用例的全部实际结果，由 runner 独立判定。实际结果包括执行后的寄存器、RAM 和每个 M-cycle 的总线状态，采用无损差分编码。用例名、初始状态和预期值由 runner 从原始套件读取，不回传。
- 测试固件在握手时报告卡上数据清单的校验值。runner 确认它和本地数据对应以后才发送运行清单，不对应就拒绝执行。
- 测试固件按运行清单从 `cases.bin` 读取选中的操作码组，逐条执行，把结果编码以后用 `send_data()` 分批回传。每个用例开始前，CPU 和内存都要回到用例给定的初始状态，上一条用例留下的状态不能带过来。
- runner 读取 `refs/tests/sm83`，按开发者指定的操作码组或单个用例生成运行清单，执行前列出用例数和跳过的原因。判定按 README 的规定进行，未定义的值不比较。用例 ID 由源文件路径和原始用例名组成。
- 使用 `sm83-stop-pc-v1` 时，runner 从 `tools/fix_sm83_stop.py` 生成的同一份修订副本读取预期值，与卡上的修订名和清单核对，并在报告中记录修订名。不能将修订套件的结果报告为原始套件的结果。
- runner 保存报告，报告里有复现所需的信息，见真机测试计划“执行和结果传输”一节的最后一段。失败的用例给出第一处差异，并且能只重跑上次失败的用例。
- 这时测试固件只有解释器，握手里如实报告可用的后端，报告中 JIT 标为 `NOT RUN`。

## 不做

- JIT，这是 1-4 和 1-5 的内容。
- 整机 ROM 的测试索引和执行，这些在里程碑 2。
- 自动重传和断点续跑。
- 根据 Git diff 自动选择测试。

## 约束

- 板上和电脑端遵守同一套外部判据。板上失败时必须返回实际结果，runner 才能报告第一处差异；默认模式没有通过用例的实际数据，不能用它的报告离线重新判定全部用例。
- 结果格式带版本号。后续修改格式时，两边要能发现版本不一致。
- 超时、板子重启、通信错误和判定失败分开报告，任何一种通信问题都不能算成通过。

## 由你决定

消息类型和记录的字段布局、runner 的命令行，以及报告文件的格式和位置。字段布局和 `frame.h` 一样写在头文件注释里，不写进文档。

## 完成标准

- 在一块板子上用解释器跑完全部单步用例，runner 判定全部通过，报告中 JIT 标为 `NOT RUN`。如果 1-1 的实现有错，就在这个任务里修。
- 确认判定真的能发现错误：临时改错一条指令的实现，runner 能指出受影响的用例和第一处差异，然后改回去。这一步不留下测试代码。
- 只重跑失败用例的功能可用。数据清单不对应时，runner 拒绝执行。

## 收尾

- 满足全部完成标准以后，在[任务状态](status.md)里把这个任务标为“已完成”。
- 测试结果保存在运行报告中；测试方法有变化时更新真机测试计划，架构和路线图只同步设计与能力。
- 向用户汇报运行结果、总耗时和遇到的问题。

## 当前实现与验证结果

SM83 的用例选择、板上解释器执行、板上判定、压缩诊断回传和失败重跑已经接通。板上判定模式通过了修订套件的全部 500,000 条用例，诊断模式通过了相关的 11,000 条用例。故障检测和异常中止检查通过。JIT 尚未接入。

验证条件、耗时和范围保存在运行报告中。执行格式见 `tests/protocol/execution.h`，使用方法见[运行 SM83 单步用例](../../hardware-testing.md#运行-sm83-单步用例)。三个板型的测试固件均能在 ESP-IDF v6.1 下构建。
