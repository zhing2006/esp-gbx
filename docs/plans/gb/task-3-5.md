# 任务 3-5：里程碑 3 验收

在板子上用两个后端跑完[路线图](../../roadmap.md)里程碑 3 的全部测试，并同步文档。做完这个任务，里程碑 3 就达到了完成标准。这个任务依赖 3-1 至 3-4，包括 [3-3.5](task-3-3.5.md)。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 路线图里程碑 2 和 3 的全部内容，尤其是完成标准和里程碑 2 的测试时间预算。
- [真机测试计划](../../hardware-testing.md)的“选择本次运行的测试”和固定回归。
- 3-1 至 3-4 的验证结论。

## 范围

- 在 Sila P4 上用测试固件的 release 构建，以两个后端运行全部 SM83 单步用例、里程碑 2 的全部 ROM，以及 `dmg_sound`、`rtc3test` 的三个子测试和 `mbc3-tester`，同时运行只记入报告的 `oam_bug` 和 Mealybug 用例。
- 3-4 改了 JIT 全部指令的代码生成和块间连接，没有运行测试。JIT 运行中被代码池淘汰过的块会改由解释器执行，不能让 JIT 的测试实际上只跑了解释器：在 JIT 上运行 ROM 时，用 `<板子>-test-profile` 版的计数确认这部分的比例，比例明显时在报告里说明。
- 里程碑 2 的测试时间预算继续适用，新增的 ROM 计入“全部 ROM”。

## 不做

- 新的功能。性能优化限于本次验收发现的瓶颈，在对应模块中修改，再验证受影响的路径。
- 把 `oam_bug` 和 Mealybug 作为完成条件。

## 约束

- 本任务是里程碑的全量验收，固定回归不能代替本次验收，也不能用随机抽样代替完整的操作码测试。
- 不能把只跑了部分模块的结果报告成整套通过。

## 完成标准

- 在 Sila P4 上，解释器和 JIT 都通过里程碑 2 的全部测试，以及 `dmg_sound`、`rtc3test` 和 `mbc3-tester`，两边结果一致，回退清单为空或者已经和用户确认。
- SM83 单步全量不超过 3 分钟，全部 ROM 在两个后端上运行完不超过 5 分钟，固定回归不超过 1 分钟。超出时先找出瓶颈，和用户确认处理办法。
- 另外两块板子的正式固件和测试固件都还能构建。

## 实现与验证

以下验收结果都来自 Sila P4，ESP32-P4 v1.3、360MHz，ESP-IDF v6.1，构建 preset 为 `sila_p4-test-release`，模拟机型 DMG-C，使用 `isolated` 调度：两个后端依次在 core 1 执行，渲染和混音在 core 0。固件包含本任务的改动，ELF 的 SHA-256 为 `68d59fabf4a2ba731e431685fa6a5f2e8e38a992284ca46aec85435fd17a8cf8`。卡上测试数据清单的 SHA-256 为 `fc1ae30952edec74cd6c89b57d49b32a209ace57c97ef819b51269756a86e814`，SM83 用例来自修订套件 `sm83-stop-pc-v1`，上游是 SingleStepTests/sm83 的 `f9c3021`；ROM 来自 game-boy-test-roms v7.0。下表的四项都在这一个固件上运行。

| 测试 | 结果 | 整次运行耗时，秒 | 预算，秒 |
|---|---|---:|---:|
| SM83 单步全量 | 500000 条在两个后端上全部通过，JIT 全部原生执行，没有回退 | 177.5 | 180 |
| 全部 ROM | 选中 130 个，129 个通过，`oam_bug` 只记录结果 | 106.1 | 300 |
| 固定回归 | 10 个全部通过 | 10.2 | 60 |
| `run_jit.py` | 106 项全部通过 | | |

SM83 的整次运行包括电脑上核对套件和用例包的约 9.6 秒，执行部分是 167.8 秒。2-6 第二轮优化以后执行部分是 159.9 秒，这之间 3-1 至 3-4 改过解释器、JIT 和共用代码，多出的 7.9 秒没有拆分来源。整次运行离预算只剩 2.5 秒。

里程碑 2 的全部 ROM、`dmg_sound`、`rtc3test` 的三个子测试和 `mbc3-tester` 在两个后端上都通过。两个后端在 130 个 ROM 上的 CPU 状态、模拟时间、执行指令数、内存摘要、帧和 PCM 摘要都相同。Mealybug 的 24 个用例只记录结果，全部通过。`oam_bug` 两个后端的画面相同，都显示“Failed #2”：01、03 和 06 通过，02、04、05、07 和 08 失败，和 2-6 时一样；它的参考图灰阶不符合套件要求，自动比较无法判定。每个后端都模拟了 229.4 秒，执行时间合计是解释器 53.304 秒、JIT 22.594 秒。3-1 报告里 `dmg_sound` 的 JIT 是 15.13×、`rtc3test` sub-second writes 是 6.46×，这次是 13.66× 和 6.10×；解释器同期从 4.20× 和 4.46× 变为 4.12× 和 4.43×。JIT 变慢的来源没有拆分。

### JIT 诊断计数

全量运行中 JIT 编译了 19204 块，失效 1974 块，淘汰 727 块。只有 `dmg_sound` 和 `oam_bug` 发生了淘汰，分别是 701 和 26 块。各类回退都是 0，回退清单为空。结束时代码池用量最大的是 `oam_bug`，227596 字节，代码池是 224KiB。

JIT 运行中改由解释器执行的部分，用 `sila_p4-test-profile` 跑一次全部 ROM 来统计。这次运行的编译、失效和淘汰次数和上面逐个 ROM 相同。130 个 ROM 的 JIT 一共执行了 92990814 条指令，其中 2132 条改由解释器执行，占 0.0023%。只有 7 个 ROM 不为 0，比例最高的是 `instr_timing`，185 条，占 0.046%。`dmg_sound` 淘汰了 701 块，改由解释器执行的只有 3 条。另外 6 个 ROM 没有淘汰，计数来自失效以后再次未命中的块：按 `Sm83Jit::execute` 的代码，重装退避和从块中间恢复只看块是否未命中，不区分它是被淘汰还是失效。所以 JIT 的测试基本都是原生执行的。

为了这项统计，`Sm83JitCounters` 增加了 `interpreted_instructions`，记录改由解释器执行的指令条数。测试固件的 profile 报告输出它和 `interpreted`，回放报告另起一行给出它和统计段执行的全部指令数。它只在 `GBX_PROFILER` 构建里存在。

### `run_jit.py` 的修正

第一次运行 `run_jit.py` 时，“JIT linked destinations after eviction, refetch and cache clear”没有通过，期望 0xf，实际 0xd，缺的是要求发生淘汰的那一位。这项检查在热路径之外编译 600 个块，让冷的目标块被淘汰。3-4 把代码池的槽数从 512 加到 1024，块也变小了，600 个块已经装得下，没有发生淘汰，所以检查的前提不成立，模拟结果本身没有错。`tests/device/mapped_blocks.cpp` 改成从 0xC400 起填满 WRAM，共 1792 个块，多于 1024 个槽。改完以后 106 项全部通过。

### 性能分析版的开销

检查了 `GBX_PROFILER` 增加的内容。正式固件的 profile 版里，JIT 计数器、每帧的计时、显示和回放的统计都是简单的计数和取时间，`prof` 和 `pstat` 只在命令运行期间工作。测试固件的 profile 版在每个 ROM 运行时都采样，开销最大。

下表用 5 个 ROM 比较几种做法的执行时间，相对 `sila_p4-test-release` 的同一批 ROM：`dmg_sound`、`rtc3test` sub-second writes、`mbc2/bits_ramg`、`intr_2_mode0_timing_sprites` 和 `mem_timing-2`。

| 做法 | 解释器 | JIT |
|---|---:|---:|
| 原来的 profile 版，每 47µs 采样 | +8.4% | +11.4% |
| 采样回调放进 IRAM | +8.6% | +11.6% |
| 不写 PSRAM 中的直方图 | +7.9% | +10.9% |
| 不采样 core 0 | +8.4% | +10.7% |
| 定时器分辨率从 1MHz 改为 40MHz | +8.4% | +11.4% |
| 不采样，只保留计数器 | +0.3% | +1.9% |
| 每 197µs 采样 | +2.3% | +4.4% |

开销几乎都来自 core 1 上的定时器中断本身，和回调做了什么无关，折算每次约 3.8µs。因此测试固件和正式固件 `prof` 的采样间隔都改为 197µs。放进 IRAM 和改分辨率都没有收益，已经撤销。改完以后全部 ROM 的执行时间，解释器比 `sila_p4-test-release` 多 2.2%，JIT 多 3.6%，原来是 8.6% 和 10.4%；整次运行从 172.4 秒降到 141.0 秒。样本相应变少，例如 `cpu_instrs` 的解释器在 core 1 上从 306722 个降到 67898 个。计数器在 JIT 上约占 2%，没有改动。正式固件 `prof` 的开销没有单独测量。
