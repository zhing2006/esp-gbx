# 任务 3-2：固件运行游戏

让正式固件能玩 GB 游戏：从 SD 卡把 ROM 载入 PSRAM，模拟固定在一个核上运行，呈现任务把游戏帧放大写进游戏窗口，触摸控件映射到 GB 的按键，声音从板上的 I2S 输出，运行节奏由音频缓冲控制。游戏页常驻的 `SPEED`、`FRAME`、`AUDIO`、`MEM` 指标，以及机型灯和后端灯也在这里接入。运行游戏的流程放在 `components/app/`，PC 版改用同一套流程和平台接口。这个任务依赖 3-1，但是画面和按键可以先做，音频部分要等 3-1 完成。主界面、菜单和存档在 3-3。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 范围

运行和画面：

- 平台接口增加读取 SD 卡文件的接口。ESP 实现使用 `/sdcard`；PC 实现把一个本地目录当作卡的根目录，下面同样是 `roms/`、`saves/` 和 `states/`。
- app 按路径载入 ROM：整个文件读进 PSRAM，按 ROM 头判断机型和卡带类型。机型或卡带类型不受支持、文件过大或读取失败时报告错误，不启动模拟。
- 模拟任务固定在 CPU 所在的核上，独占 `gb::System`。PPU 渲染、APU 合成、呈现、LVGL、触摸和音频提交在另一个核上，核的安排和测试固件一致。两个后端都要能运行；在 3-3 接入 SETTINGS 之前，选择后端的方式可以是临时的。
- 呈现任务把 BGR555 的游戏帧转换成面板的格式，按 2 倍最近邻放大，居中写进 480×320 的游戏窗口，其余部分填黑。UI 的复制避开游戏窗口。P4 可以用 PPA，没有 PPA 的芯片用软件缩放；JC1060P470 要按 UI 的方向旋转。每个游戏帧带单调递增的帧 ID，呈现任务只在出现新帧时复制。
- 屏幕上的方向键、A、B、Start、Select 映射到 GB 的按键，方向键的 8 个方向和多指同时按都要支持。按键状态在帧边界提交给系统。速度拨杆暂时不接，MENU 键在 3-3 接入。

声音和节奏：

- 平台接口增加音频输出：按给定的采样率打开输出、提交 PCM、查询待提交队列的水位，以及音量、静音、暂停和恢复。ESP 实现放在 `components/platform/src/esp/`，codec 和功放的差异放在 `boards/<板子>/`；PC 实现使用 SDL3。
- Sila P4 和 JC1060P470 是 ES8311 加单声道功放 NS4150，Tab5 是 ES8388，它的喇叭只接了左声道。输出到单声道喇叭时，先把 GB 的立体声混成单声道。功放的使能脚按板子文档控制。codec 的控制可以使用乐鑫组件，在 `idf_component.yml` 里锁定版本。
- 环形缓冲和 I2S DMA 只用来吸收短暂的抖动。模拟任务按缓冲的水位推进，水位偏离目标时小幅调整 3-1 的重采样比例，调整幅度有上限。持续的性能不足表现为速度下降和欠载，不能用大幅变速掩盖。画面仍然单独提交，不随音频节奏补帧或丢帧。

常驻指标：

- `SPEED` 按调试设计的公式计算，布局有空间时显示 `EMU` 和 `DRW`；显示后端还不能确认缓冲实际切换的时刻时，`DRW` 显示未采集。`FRAME` 显示每帧工作耗时的 p95、平均值和有效样本数，计时的起止点按调试设计“每帧工作耗时”一节。`AUDIO` 显示待提交队列的时长、欠载的累计次数和本窗口增量，以及本窗口最低水位。暂停和预填充期间不计欠载。正常播放时，输出端需要 PCM 而供数不足就计为欠载，主动静音不影响计数。游戏本身输出的静音 PCM 属于正常供数，不算欠载。`MEM` 分开查询片内和 PSRAM 的空闲量。
- GB 机型灯，以及 INT 和 JIT 后端灯。运行状态不是 `RUN` 时显示在 `SPEED` 格里，本任务接入 `NO ROM`、`LOADING`、`RUN` 和 `ERROR`。
- 未采集、不支持、过期和预热分别按 telemetry-fields.json 显示。加载 ROM 和切换后端时，按调试设计重置统计窗口。PC 版用 Tab5 的布局显示同样的指标。

测量用的游戏：

- Dangan GB（Snorpung、Nordloef）：MBC1，没有卡带 RAM，DMG 专用。游戏中它反复轮询 LY 和 STAT，适合测量渲染负载和跳过忙等。用户本地的副本是仓库根目录下的 `roms/gb/dangan.gb`，SHA-1 `10029774046dabec2d8c0533caf94091f6e19071`。
- 用户另外提供了两个商业游戏，也放在 `roms/gb/`，`.gitignore` 已经排除了 `roms/`。它们只用于本地的性能分析和人工检查：不提交，不写进 fetch 脚本，不进入测试索引，也不作为任何测试的判据，报告里和 Dangan GB 的数据分开写。

## 约束

- 模拟所在的核上不做格式转换、缩放、呈现、UI 绘制、I2S 提交和指标汇总。模拟任务只在帧和音频块的边界交接画面、PCM 和计数，每条指令、每次访存和每个周期的路径上没有为本任务增加的操作。
- 节奏控制只决定模拟什么时候运行，不改变模拟时间线和模拟结果。
- 另一个核上的工作较多，呈现和 UI 不能让渲染任务长时间排不上，导致 CPU 所在的核等待；音频任务的优先级要保证输出不会因为 LVGL 绘制而饿死。各任务所在的核和优先级写进代码注释。
- PPU 的渲染线程处理完已提交的扫描线以后，会先轮询一段时间再睡眠，长度是 `components/core/src/gb/ppu.cpp` 的 `Renderer::kPolls`。测试固件的 core 0 上没有别的工作，轮询省掉了 CPU 所在的核唤醒它的开销；但是新行来得慢时，轮询会占去 core 0 的大量时间。2-6 用性能分析版测试固件测过：解释器运行 `cpu_instrs` 时，轮询约占 core 0 的 64%。正式固件的这个核上还有呈现、LVGL 和音频，要在实际负载下重新确定轮询的长度，或者按上一次是否等到新行来决定要不要轮询，并确认它不会让优先级更低的任务长时间排不上。
- JIT 的代码池需要 224KiB 连续的片内可执行内存。`gb::System` 和 ROM 放在 PSRAM，卡带 RAM 已经由 `platform::allocate_external()` 放进 PSRAM。正式固件接入模拟、LVGL 和 I2S 的 DMA 缓冲以后，其他不在热路径上的大块数据也要放进 PSRAM，片内留给代码池和必须在片内的缓冲。
- 游戏窗口按帧切换缓冲，不能撕裂，也不能复用还没有显示完的缓冲。
- UI 只读取已经完成的指标快照，不能持锁阻塞模拟线程。计数和样本使用固定容量的缓冲。
- 板子的初始化和 codec 的配置以板子文档和原理图为准，核对功放的实际供电和增益，不照抄示例里的参数。
- `core`、`jit`、`app` 和 `ui` 不 include ESP-IDF 的头文件。
- 在 3-3 接入主界面之前，开发期间可以用固定路径之类的临时方式指定要载入的 ROM。这部分代码不提交。

## 完成标准

- 在 Sila P4 上测量呈现每帧的复制、转换和缩放耗时，音频提交和指标汇总的耗时，另一个核的负载，以及 CPU 所在的核等待渲染、合成任务的时间，针对测量结果优化，并核对代码大小和缓冲占用。3-1 的性能分析显示，CPU 所在的核跑到 20 倍原速以上时，core 0 被渲染占满（见 [3-1 的剩余瓶颈](task-3-1.md#剩余瓶颈)）；渲染和另一个核的负载在本任务和 3-4 处理。测量至少包括 Dangan GB 和本地的 Pokémon Gold、Pokémon Yellow，Yellow 要包括播放皮卡丘叫声的一段。在 JIT 初始化之前记录片内最大的可执行连续块，确认代码池还有余量。用解释器和 JIT 分别运行同一个 ROM，记录两边的模拟速度。如果改动了模拟核心，按[双后端优化要求](../../hardware-testing.md#每个任务的双后端优化)处理。
- 在 Sila P4 上，正式固件用两个后端都能载入并运行 `dmg-acid2`、blargg 的 `cpu_instrs`，画面与套件的参考图目测一致。这只是手动检查，不作为测试判定。
- 按下屏幕上的各个按键，包括同时按方向键和 A、B 时，ROM 读到的按键寄存器随之变化。可以用日志或者能显示按键状态的 ROM 确认。
- 核对指标的口径：用一段较长的运行，按日志里的模拟时间和墙钟时间独立计算速度，与 `SPEED` 一致；`FRAME` 的 p95 和临时记录的帧耗时样本一致；临时让模拟变慢以制造欠载，`AUDIO` 的计数随之增加。确认以后去掉临时代码。测量常驻采集在两个后端上的开销，写进报告。
- PC 版用 app 的流程运行 ROM，能播放声音并显示同样的指标，命令行用法和键盘映射保持不变。GUI 和无窗口的 debug、release 构建都能编译，现有的 CTest 检查通过。Windows 上如果没有运行，汇报时写明未验证。
- 如果在 JC1060P470 上运行过，确认游戏画面和触摸的方向。
