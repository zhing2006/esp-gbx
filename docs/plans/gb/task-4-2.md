# 任务 4-2：即时存档的文件和菜单

在暂停菜单里加入即时存档和读档，共 4 个槽位，每个槽位一个文件。编码和写卡在另一个核上进行，模拟只在复制状态时暂停。这个任务依赖 3-5，和 4-1 一起做，使用 4-1 的状态接口。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- [路线图](../../roadmap.md)里程碑 4 的全部内容，尤其是完成标准。
- [产品设计](../../product-design.md)的“SD 卡目录”和“存档”，[调试设计](../../debug-design.md)中存档状态的定义。
- [UI 布局](../../ui-layouts/index.md)中 3-3 设计的暂停菜单，以及 3-3 的卡带存档写回、RTC 补算和断电测试方法。
- 4-1 的状态接口。

## 范围

- 界面设计：暂停菜单的 DEBUG 换成一个 SAVE / LOAD 入口，进去以后先选槽位，再选存档还是读档。设计包括槽位列表以及覆盖、读档时的提示，沿用 3-3 的风格，写进 UI 布局文档。设计先交给用户确认，确认以后再实现。槽位上显示哪些信息，比如缩略图，在设计里定下来。
- 界面上不用 STATE 这个词。槽位和槽位的提示用 SLOT 称呼，比如 `SLOT 2`，和卡带存档的 SAVE 区分开。
- 主界面去掉 DEBUG 入口，其余卡片的高度和位置不变，空出来的一格留给以后的入口。
- 文件放在 `states/` 下与 `roms/` 相同的子目录里，名字是 `<ROM 名>.<槽位>.state`，槽位从 1 到 4，比如 `roms/gb/rpg/Pokemon Yellow.gb` 的第 1 个槽位是 `states/gb/rpg/Pokemon Yellow.1.state`。每个文件记录格式版本、ROM 头的标识、校验、4-1 的状态，以及存档时板上 RTC 的时间和它是否可信。
- 即时存档：选中槽位以后，模拟所在的核复制状态，另一个核编码、写文件并刷新存储。覆盖已有的槽位之前先确认。写入期间界面显示进度，QUIT 要等写入完成。
- 读档：版本不同的存档不读取，并提示原因。ROM 头的标识和当前 ROM 对不上时，先提示用户，再按用户的选择读取或者不读。校验不通过的槽位显示为损坏。
- 卡带 RAM 和 RTC 跟着状态一起恢复，读档之前不为卡带存档另外提示。读档以后卡带存档标记为脏，按 3-3 的流程写回。
- 读档时，如果存档时和现在的板上 RTC 时间都可信，把这段时间用 3-1 的接口补算到 RTC 上，和关机期间的补算相同。不可信或者时间倒退时不补算，并且提示。
- PC 版使用同一套界面和文件格式，存档写在本地目录里。

## 不做

- 自动即时存档，比如退出游戏时自动存一份。
- 旧版本存档的迁移，以及 GBC 和 GBA 的即时存档。
- 每个槽位轮流写两个文件。写到一半掉电时，只有正在写的槽位可能损坏。

## 约束

- 模拟所在的核只在复制状态和恢复状态时暂停，编码、校验、写文件和刷新存储都在另一个核上。
- 写即时存档不能动卡带存档的文件，也不能动其他槽位的文件。
- 写完以后刷新存储，确认成功才把这个槽位显示为有效。FAT 上的一次 rename 不能当作掉电安全的保证。
- 文件格式写在代码注释里，文档只写约定。

## 由你决定

文件的格式和校验算法、槽位上显示的信息、写入进度的显示方式，以及界面流程在 app 和 ui 之间的划分。界面部分在设计阶段由用户确认，其余的理由写在代码注释里。

## 完成标准

- 设计已经由用户确认。UI 布局文档有新界面的说明和效果图，`render_previews.py --check` 通过。
- 在 Sila P4 上，正式固件可以用 4 个槽位存档和读档，在解释器上存、切换到 JIT 以后读，以及反过来都能正常继续游戏。覆盖确认、版本不同、ROM 标识不符和槽位损坏的提示都按设计出现。检查时用 3-2 列出的本地 Pokémon Yellow，它有 32KiB 带电池的卡带 RAM，读档以后卡带存档按 3-3 的流程写回。
- 在 Sila P4 上测量存档和读档时模拟所在的核的暂停时间。
- 在 Sila P4 上做写入中断测试：在写即时存档数据的期间用 CH340 的 RTS 复位芯片，做 1 次。芯片复位不切断 SD 卡的供电，所以这项测试检查的是槽位文件的写法能不能在写到一半时保住其他文件，不包括卡本身在掉电时写坏的情况。重启以后，其他槽位和卡带存档都能正常读取；正在写的槽位要么是完整的新存档，要么显示为损坏，不能读出半份数据。
- PC 版的即时存档和读档可以用，GUI 和无窗口的构建都能编译，现有的 CTest 检查通过。
- 另外两块板子的正式固件和测试固件都还能构建。
