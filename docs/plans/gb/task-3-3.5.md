# 任务 3-3.5：UI 硬件加速和游戏缩放设置

优先评估并接入与游戏画面无关的 LVGL UI 加速，再处理游戏画面的呈现。在 SETTINGS 中增加最近邻和平滑两种缩放模式，ESP32-P4、ESP32-S31 的平滑模式使用 PPA，有平滑实现的平台默认使用 SMOOTH，否则使用 NEAREST。保留完整的 CPU 显示实现供 ESP32-C5 使用，但固件按编译目标选择后端，不把两套完整实现一起编入。这个任务依赖 3-2 和 3-3，可以和 3-4 分别推进；性能比较时要固定同一份模拟核心和构建配置。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- [架构](../../architecture.md)的“显示和触摸”“板子”，以及 `components/platform/src/esp/display.cpp`、PC 显示实现和板级显示接口。
- [UI 布局](../../ui-layouts/index.md)的菜单、SETTINGS 和游戏窗口约定，以及 [3-3](task-3-3.md)的设置持久化和暂停流程。
- [真机测试计划](../../hardware-testing.md#每个任务的双后端优化)和[调试设计](../../debug-design.md)中的性能口径，尤其是异步任务的提交耗时与完成耗时。
- 乐鑫的 [P4 PPA 文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/peripherals/ppa.html)、[S31 PPA 文档](https://docs.espressif.com/projects/esp-idf/en/release-v6.1/esp32s31/api-reference/peripherals/ppa.html)和 [DMA2D 驱动文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s31/api-reference/peripherals/async_color_convert.html)，并核对本机 ESP-IDF v6.1 的驱动、SOC 能力宏和芯片修订限制。P4 和 S31 都有 PPA 与 2D-DMA。
- 当前使用的 LVGL PPA 后端及其限制。`LV_USE_PPA` 用于乐鑫 PPA；LVGL 的 `LV_USE_DRAW_DMA2D` 对应 STM32，不能用它开启乐鑫的 2D-DMA。

## 范围

### 最高优先级：UI 加速

- UI 加速独立于游戏的缩放选项。选择 `NEAREST` 时，已确认有收益的 UI 加速仍然启用。
- 先测量主界面、ROMS 列表、SETTINGS、暂停菜单和游戏页常驻控件的绘制。覆盖首次显示、切换页面、列表滚动、调整设置和小区域刷新，区分 LVGL 绘制与呈现任务中的复制、旋转和显示提交。
- 评估并接入 LVGL 的 PPA 后端，用于适合硬件处理的填充、图像复制和混合。核对透明度、遮罩、文字和图像格式的支持范围，未覆盖的 LVGL 绘制继续由其软件绘制器完成。不能因为启用了 PPA，就认为全部 UI 操作已经加速。
- 用 2D-DMA 处理不需要旋转的 UI 脏矩形复制；用 PPA 处理需要旋转的矩形，缩放比例保持 1。优先覆盖 JC1060P470 的 UI 方向转换。游戏窗口填黑和其他大面积填充也纳入测量。
- 保留现有脏区域更新、游戏窗口避让和双缓冲交换规则，避免为局部变化增加整屏复制。小区域是否交给硬件，由提交、缓存同步和完成等待都计入后的耗时决定。
- 先完成 UI 的功能验证和性能比较，再确定各目标启用哪些加速操作，不预设所有操作都比 CPU 更快。

### 游戏画面和 SETTINGS

- 主界面与暂停菜单的 SETTINGS 共用一项 `SCALING`，选项为 `NEAREST` 和 `SMOOTH`。最近邻保持原来的整数倍像素复制；平滑在有可用加速后端的 ESP 目标上使用 PPA 的双线性缩放。两种模式使用相同的游戏窗口、整数倍尺寸、居中位置和黑边，不顺带增加拉伸或铺满模式。
- PPA 的缩放使用双线性插值，不能用它代替最近邻。加速后端允许保留最近邻所需的 CPU 像素处理，也允许在交给 PPA 之前用 CPU 把 BGR555 转成 RGB565。模拟核心继续输出 BGR555，不为显示后端改变 PPU 的输出格式。
- 平滑模式把缩放和面板方向转换尽量合并在同一次 PPA 操作中。最近邻模式是否在 CPU 放大以后再用硬件旋转，按包含中间缓冲读写在内的完整耗时决定。
- 暂停时可以切换模式，恢复游戏后生效，不重置模拟状态。设置在重启以后保留。新增设置项时兼容 3-3 已保存的其他设置；用户明确保存的缩放选择不能被默认值更新覆盖。
- PC GUI 使用同一项设置，分别选择 SDL 的最近邻和平滑采样。CPU 显示后端保留最近邻；没有可用平滑实现的目标将整行 `SCALING` 置灰、禁止修改，固定选中 NEAREST。设置文件中保存了当前不支持的 `SMOOTH` 时，自动回退到 `NEAREST`，界面选中 NEAREST，不阻止启动或恢复游戏。
- 各目标在没有用户选择时，有平滑实现的默认使用 SMOOTH，否则使用 NEAREST。两种模式都必须满足显示正确性和稳定性要求，并比较完整呈现耗时、CPU 占用、实际显示帧率及音频欠载。默认画质按这条规则选，不标成所有指标都最快；未实测目标不推断性能，不在运行时自动切换画质。

### 编译时选择显示后端

- 完整的 CPU 显示实现保留在源码中，包括颜色转换、最近邻放大、旋转、UI 复制和填充，供 ESP32-C5 等目标使用。不能因为 P4 或 S31 的硬件加速更快就删掉这套实现。
- 在构建时按 SoC 选择 CPU 或加速显示后端，不以每块板子重复测试作为启用条件。P4 统一启用加速；S31 先按硬件能力准备加速配置，但不声称已经实测。P4、S31 的加速构建不编入完整 CPU 显示后端；C5 配置选择 CPU，不引入 PPA、2D-DMA 显示实现及其驱动依赖。不通过运行时开关保留两套完整后端。
- 加速后端中的格式转换、最近邻像素处理，以及 LVGL 对硬件未覆盖操作的软件绘制，不属于完整 CPU 显示后端。这些必要步骤可以编入加速固件，职责和编译边界要写清楚。
- 用 ESP-IDF 的 SOC 能力宏和组件依赖表达硬件要求，不把加速实现写成只允许 P4 使用。PC 的 SDL 后端保持独立。S31、C5 的板级接入不属于本任务；没有对应硬件时写“未实测”，不能从 P4 的结果推断其他芯片的收益。

### 刷新节奏和音频记账

- 所有板子以 GB/GBA 的 `4194304 / 70224 ≈ 59.7275 Hz` 为刷新目标，分别选择像素时钟和时序，并考虑 DPI 分频与 DSI 行计数取整。不把厂商示例的默认时序当作目标帧率。
- 显示帧率标签使用 `DRW`，计数仍然是新游戏帧首次成为扫描来源的次数。
- 音频节流水位包含已经提交但尚未混音的 PCM。混音只是将待处理音频变为可读取 PCM，不增加已记账总量；读取、复位丢弃和输出溢出需要正确扣除。播放线程仍只读取已经完成的 PCM。
- 呈现任务优先级保持 4，不通过提高优先级或增加显示队列掩盖供帧节奏问题。

## 约束

- ESP-IDF 驱动和缓存操作留在平台层，上层通过显示接口选择缩放模式。PPA、DMA2D 的句柄和缓冲在初始化或切换显示配置时准备，不在每条指令、每个周期的路径中分配。
- 异步操作完成以前，不能交换输出缓冲、重用输入帧或让 LVGL 改写正在被读取的 UI 区域。正确处理 CPU 与 DMA 之间的缓存同步和输出缓冲对齐，避免 CPU 写回旧缓存覆盖硬件的结果。
- 维持 PPU、APU 与呈现任务的核安排和同步要求。性能比较包含同时运行模拟、声音和 UI 时的 PSRAM 竞争，不能只用一张静态图的硬件耗时判断实际收益。
- 游戏测试仍在原始分辨率的模拟输出上按套件自己的判据判断。平滑后的面板图不能作为原机参考图，也不能录制模拟器的输出充当 golden image。
- 新增性能分析代码全部放在 `GBX_PROFILER` 内，包括呈现总耗时计数器，不为测量在正式 release 中保留例外。本任务的性能比较只使用分析构建，注明 profiler 的开销，不另做正式 release 的性能复测。
- 显示代码的变化不能破坏既有热代码布局；检查链接 map 中解释器、设备执行代码和 JIT 运行时的地址。记录代码体积、片内 RAM、PSRAM 和 JIT 可用连续块的变化。

## 不做

- ESP32-S31、ESP32-C5 的新板级支持及其整机验收。
- 改变 GB PPU 行为、增加 GBC 或 GBA 功能，以及新的缩放比例和画面滤镜。
- 在 CPU 后端增加软件平滑缩放，或者在运行时加载另一套完整显示后端。

## 由你决定

CPU 与加速后端的文件划分、共用像素处理函数、硬件任务的批量提交方式、中间缓冲的大小，以及小区域交给 CPU 还是硬件的阈值。决定依据写在代码注释中，最后向用户说明。两个缩放选项都保留。有平滑实现的平台默认使用 SMOOTH，没有平滑实现时使用 NEAREST；后端和小区域处理策略仍按实测选择。

## 完成标准

- 在可用的 P4 板子上，先完成 UI 加速前后的比较：分别列出各类界面的 LVGL 绘制耗时、复制与旋转耗时、硬件提交到完成的耗时、CPU 占用和缓冲占用。确认有收益的操作进入对应目标的加速实现，最后向用户说明没有收益的尝试及其原因。
- 用已知颜色和坐标的图案检查矩形复制、旋转、最近邻复制和窗口边界，确认没有越界、色序错误或未修改区域损坏。平滑按 PPA 的插值规则检查，不要求它和最近邻像素相同。图案检查不代替实际面板的外观检查。游戏窗口与 UI 互不覆盖，暂停、恢复和切换缩放模式后显示正常。
- 用两个执行后端和两种缩放模式运行相同的代表性 ROM、初始状态、输入及统计区间。至少使用 Dangan GB；本地商业游戏只作补充实测，不作为可重现测试的必要条件，也不提交 ROM。已有回放可用时复用，不能依赖尚未完成的 3-4 才能开展测量。
- 性能分析构建记录已有的 `SPEED`、`EMU`、`DRW`、`FRAME` p95、音频欠载与两个核的负载，以及呈现和各阶段耗时。注明板型、芯片修订、主频、IDF 版本和显示配置，不把带 profiler 的数据当作正式 release 的测量值。原速节流下两种模式的帧率相同时，还要比较呈现耗时和 CPU 占用。最后向用户说明各目标默认模式的选择依据，以及尚未测量的目标。
- SETTINGS 的两种模式、暂停切换、持久化和旧设置读取按约定工作，更新默认值不会覆盖用户已经保存的选择。两个执行后端的模拟结果一致，并按真机测试计划完成受影响范围的检查。
- 检查构建源文件、依赖和链接 map：同一套固件按目标选择显示实现，确认硬件加速更好的 SoC 统一编入加速显示后端，不支持硬件加速的 SoC 使用 CPU 显示后端。保留 CPU 实现供这些目标接入，不要求在 P4 上额外交付或验收纯 CPU 显示构建，也不为此裁剪 SDK 或第三方面板驱动自带的代码。未接入 C5 板子时不声称已经完成 C5 真机验证。
- 现有板子的正式固件，以及 PC GUI 和无窗口构建通过相关检查。实际接入过的旋转方向要在板上检查；没有对应板子的方向注明未实测。

- 更新架构、产品设计、UI 布局和 PC 使用说明中的后端选择、缩放设置与默认行为；用 `tools/ui/` 更新 SETTINGS 效果图并检查。保留完整 CPU 实现供 C5 使用的约束要继续写在架构中。

## 完成情况

任务已完成。P4 的四款板子共用加速显示配置，保留完整 CPU 实现供不支持加速的 SoC 使用。S31 的加速配置和 C5 的 CPU 配置已准备，板级接入未包含在本任务中。SETTINGS、持久化、暂停切换、PC 采样和不支持平滑时的整行禁用均已接入。有平滑实现的平台默认 SMOOTH，其他平台默认 NEAREST。

显示优化包括 LVGL PPA、DMA2D 矩形复制、PPA 旋转与填充、平滑缩放，以及被完整覆盖的脏矩形去重。平滑预转换复用连续同色像素的结果，菜单 2 倍放大使用整字写入。DMA2D 保留两个事务槽，避免完成回调早于事务回收时无法再次提交。平滑转换缓冲为 240×160 RGB565，共 75KiB，没有新增放大后的中间帧。

四款板子的时序都已改为接近 GB/GBA 刷新率。Sila P4 与 Sila P4X 的计算值约 59.7286Hz，Tab5 约 59.7286Hz，JC1060P470 的 DSI 主机时序计算值约 59.7300Hz。板子文档保留配置与计算依据，不记录验证过程。

音频节流使用 `audio_buffered()`，把已提交但尚未完成混音的音频计入水位，避免重复补同一个缺口。`audio_queued()` 保留可读取 PCM 的含义，供播放和状态显示使用。呈现优先级保持 4，三槽交接和只取最新帧的规则不变。临时优先级试验接口、菜单分项计时和矩形测速代码已移除；显示阶段、帧交接和硬件完成耗时的通用诊断保留在 `GBX_PROFILER` 内。

### 检查与测量

测量平台为 Sila P4，ESP32-P4 v1.3、360MHz、PSRAM 200MHz、720×720 RGB565，ESP-IDF v6.1，LVGL 9.6.0~1。以下性能数据都来自 profile 构建，包含其开销。

- UI 加速初次对照中，HOME 焦点切换的 LVGL 平均绘制耗时约 21.34→11.71ms，ROMS 导航约 24.36→13.30ms。小区域保留软件处理，未将全部操作交给硬件。
- 脏矩形去重的单独对照中，HOME 每次呈现的 UI 复制约 3.39→1.76ms，ROMS 滚动约 3.97→2.01ms。菜单整字写入没有单独计时，不单独报告收益。
- 普通测试固件的显示图案检查共 100 项通过；音频记账检查的 14 个检查点通过，覆盖阻塞混音时的待处理数量、采样率与速度变化、跨批次小数余量、读取、复位和溢出。
- 固定回归的 10 个 ROM 均按各套件判据通过，解释器与 JIT 结果一致。最后一例曾因 PC 替换结果文件时的权限错误中断，单独重跑通过。

音频水位修复后的 Dangan GB 对照保持呈现优先级 4。每组重新载入游戏，预热 8 秒，采样 12 秒。FRAME 一列是窗口内上报 p95 的均值。

| 执行方式 | 缩放 | DRW，fps | FRAME，ms | 取走前覆盖数 |
|---|---|---:|---:|---:|
| INT | NEAREST | 59.73 | 3.47 | 0 |
| INT | SMOOTH | 59.75 | 3.15 | 0 |
| JIT | NEAREST | 59.74 | 2.63 | 0 |
| JIT | SMOOTH | 59.68 | 2.66 | 0 |

四组均约 100% SPEED，音频欠载为 0；交接窗口合计 2901 次发布，全部取走，没有小于 5ms 的连续发布。用户观察到画面改善。此前提高呈现优先级可以减少覆盖，但增加了部分组合的 FRAME 耗时，因此未保留该改动。

### 验证边界

- S31、C5 未实测。其他三款 P4 板子的新刷新时序未上板实测，不从 Sila P4 的结果推断其物理面板表现。
- 四款 P4 release、PC GUI 和无窗口构建在显示功能接入阶段通过检查。音频记账修复使用 Sila P4 普通测试固件和 profile 固件验证；最新音频改动后的其他板子及 PC 构建未重跑。
- 音频记账改动前后的 profile 镜像为 907888→908400 字节。APU、混音器、RTC 和 Offload 区域的地址发生变化；排在它们之前的解释器、PPU、JIT 运行时和块查找地址未变。这个体积差不是最终 release 的体积差。
- 本轮收尾删除试验接口、整理注释和文档，没有重新编译、测试或刷机。板上保留已验证的 profile 固件，呈现优先级为 4，测试静音已解除。
