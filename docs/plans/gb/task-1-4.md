# 任务 1-4：JIT 后端基础

新建 `components/jit/`，提供 RV32 指令编码、放在可执行内存里的代码缓存，以及生成代码以后的缓存同步，并约定 C++ 和生成的代码之间怎么互相调用。1-5 的 SM83 前端建立在它上面，以后 GBA 的 ARM 前端也会用它。这个任务不依赖 1-2 和 1-3，可以和它们同时进行，但是要在板子上验证。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- [产品设计](../../product-design.md)的“目标平台”“执行与 JIT”和“内存布局”。
- [架构](../../architecture.md)的“分层”和“板子”：芯片差异放在 `components/platform/src/esp/`，jit 组件只能 include 平台接口。
- `refs/docs/riscv-isa/` 中的 RV32I、M、Zifencei 规范，以及 `refs/docs/riscv-psabi/` 中的调用约定。版本由 `refs/fetch.sh` 和 `refs/fetch.ps1` 固定。
- ESP-IDF v6.1 的内存保护配置、芯片内存布局和缓存同步接口，来源见架构文档“JIT 后端”一节。

## 范围

- 平台接口增加可执行内存的分配和缓存同步，ESP 上的实现放在 `components/platform/src/esp/`。PC 版没有 JIT，所以 PC 上的实现不需要能执行生成的代码，但是 jit 组件要能在 PC 上编译。
- RV32 编码先覆盖 RV32IM 里前端要用的指令。压缩指令和 Zb 等扩展不在这个任务里，因为 Zb 包含哪些子集还要按芯片修订核对，见产品设计“目标平台”一节。
- 代码缓存在初始化时一次分配代码池，编译时从池里取空间，能按块标识查找，也能整体清空。块标识的内容由前端决定，后端不解释它。
- 进出生成代码的约定：从 C++ 进入一个块，块结束时带着退出原因返回；块里可以调用 C++ 函数，1-5 的访存和总线记录都要靠这种调用。约定里要写清楚哪些寄存器由谁保存。

## 不做

- 寄存器常驻、块间链接和快速访存。这些属于[路线图](../../roadmap.md)里的后续优化，快速访存安排在里程碑 5。
- PSRAM 里的冷代码区。这个里程碑只需要片内的一个代码池。
- 按 bank 映射或代码改写让单个块失效，以及 JIT 诊断。这些在里程碑 2。

## 约束

- 后端里不能出现 SM83 的概念，因为 ARM 前端也要用它。
- 生成代码以后，要写回数据缓存并让指令缓存失效，否则 CPU 可能执行到旧的代码。先保证在一个核上正确；双核之间的同步要求写进注释，等做双核分工时再实现。
- 在公共 `sdkconfig.defaults` 关闭 `CONFIG_ESP_SYSTEM_MEMPROT`，对所有板子的正式固件和测试固件生效，让片内代码池可以写入并执行。文档必须说明它取消了代码/数据权限划分，不能写成关闭所有地址保护。
- 代码里不要假设芯片一定是 P4，以后 S31 也要跑。芯片差异按 SOC 能力宏区分，见架构文档“板子”一节。

## 由你决定

后端的接口形式、代码池的大小和管理方式，以及编码函数的组织方式。

## 验证

在板子上真正执行生成的代码，至少覆盖算术、分支、调用 C++ 函数后返回，以及改写一段已经执行过的代码以后再执行，确认执行的是新代码。指令编码可以和 ESP-IDF 工具链里汇编器的输出对照。如果要把这些检查留成长期测试，就接进 runner 和测试固件的通路，不要另起一套。

## 完成标准

- 上面的验证在一块板子上全部通过，并写明板子、芯片修订和主频。
- PC 版能编译 jit 组件，三块板子的正式固件和测试固件都还能构建。

## 收尾

- 满足全部完成标准以后，在[任务状态](status.md)里把这个任务标为“已完成”。
- 在架构文档中说明 JIT 后端的模块边界，以及可执行内存和缓存同步里不写下来就容易出错的约束。
- 向用户汇报内存保护是怎么处理的，以及代码池放在哪里。

## 实现与验证

RV32I/M 编码、有限容量的代码生成缓冲、片内代码池、块查找和整体清空已经实现。生成代码与 C++ 使用标准 ABI 互调，缓存发布由平台层负责。公共配置关闭代码/数据权限划分，代码池不使用 PSRAM。接口和生命周期约束见[架构](../../architecture.md#jit-后端)。

原生代码检查复用 runner 和测试固件的传输通路，不代表 SM83 JIT 已经接入。运行方法、验证条件和结果集中在[真机测试计划](../../hardware-testing.md#jit-后端检查)。
