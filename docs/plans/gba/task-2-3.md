# 任务 2-3：PPU

实现 GBA 的 PPU：背景、OBJ、仿射变换、混合、窗口和 mosaic，在另一个核上按扫描线渲染，输出 240×160 的 BGR555 帧。runner 从这里开始用 1-2 的参考帧比较画面。两个后端同时实现。这个任务依赖 2-2。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 路线图 GBA 段里程碑 2，[产品设计](../../product-design.md)的“双核分工”和“正确性验证”。
- [架构](../../architecture.md)的“双核分工”和“PPU 渲染”：GB 的扫描线任务怎样带上寄存器和显存的修改。
- `refs/docs/gbatek.htm` 中 “GBA LCD Video Controller” 下的全部小节。
- 1-2 的参考帧和 PPU 测试 ROM 的源码，以及 nba-hw-test `ppu` 下各测试的 README。
- [真机测试计划](../../hardware-testing.md)中画面比较的规则，以及 1-2 写下的参考帧的判据。

## 范围

- 模式 0 至 2 的图块背景和仿射背景，模式 3 至 5 的位图和帧选择，BG 的控制、滚动和优先级。仿射背景的参考点在每帧开始时锁存，每行按 dmx、dmy 累加，程序在帧中途写参考点寄存器时立即生效（GBATEK “LCD I/O BG Rotation/Scaling”）。
- OBJ：OAM 属性，普通和仿射 OBJ，double size，1D 和 2D 映射，和 BG 的优先级，半透明，OBJ 窗口，以及每行的 OBJ 绘制周期上限和 DISPCNT 的 H-Blank Interval Free 位。
- 窗口 0、1、OBJ 窗口和窗口以外的区域，BLDCNT、BLDALPHA 和 BLDY 的混合和亮度调节，BG 和 OBJ 的 mosaic，强制空白，以及 nba-hw-test 测的 green swap、DISPCNT 的锁存和 VRAM 的镜像。
- DISPSTAT 和 VCOUNT 的中断，以及 VCOUNT 匹配和 HBlank、VBlank 中断与 DMA 的时序（nba-hw-test `ppu/status-irq-dma`）。
- 按 GB 段的双核分工，CPU 所在的核按扫描线把渲染任务交给另一个核，任务带上这一行用到的寄存器，以及 VRAM、调色板 RAM 和 OAM 的修改和发生的时刻，另一个核只读取任务和自己持有的副本。GBA 的 VRAM 有 96KiB，修改的记录粒度和副本的更新方式按实测的开销定。
- 一行中途修改的寄存器和显存，按写入的时刻分段生效，没有中途修改的行一次画完。不保证生效的像素位置和原机完全相同。
- 系统接口加上取帧和 `FrameSink`，取帧时先等已经提交的渲染任务完成。测试通路回传 BGR555 帧，runner 按 1-2 的规则在规定的帧取帧，和参考帧逐像素比较，不做容差。失败时保存实际帧和标出不同像素的差异图。
- 测试索引中 PPU 的 ROM 和需要比较画面的 ROM 改为具备执行条件。

## 不做

- 逐点模拟 PPU 的取图过程。
- CPU 访问 VRAM、调色板 RAM 和 OAM 时和 PPU 争用带来的额外等待，除非必过的用例需要；需要时先和用户确认做法。
- 2X 时跳过不显示的帧，这在 6-2。

## 约束

- 写代码时就要注意性能，解释器和 JIT 都一样。在满足功能的前提下选性能最好的实现，不写明显低效的代码，也不留给以后的优化任务再改。
- 画面和参考帧不一致时，先查 GBATEK 和硬件测试确认哪一边正确，不直接照着参考模拟器改，也不阅读参考模拟器的实现。确认是参考帧有错时，先和用户商量；卡上的测试数据不在这个任务里改动。
- 渲染核只使用任务里的数据，不读取 CPU 正在修改的实时状态。任务队列满时 CPU 所在的核等待，不丢弃任务。
- 每次访存的路径上只为 VRAM、调色板 RAM 和 OAM 的写入记录修改，其他访问不增加开销。
- PPU 和渲染器按 `cmake/core_layout.cmake` 的规则放在执行代码之后，修改 PPU 不能移动解释器、内存和 JIT 运行时的代码，也不能移动 GB 的热代码。
- 开发期间只构建要刷进板子的测试固件和 PC 的 debug 版。做完一段开发才上板，只运行 PPU 的 ROM 和与它有交互的用例。
- 回退、测试时间和回传大小沿用 2-1 的规则。

## 完成标准

- 按[双后端优化要求](../../hardware-testing.md#每个任务的双后端优化)，测量渲染核每行的耗时和 CPU 所在的核为渲染任务多出的开销，用画面复杂的测试 ROM 分析和优化，提交优化前后的数据和剩余瓶颈。
- 在 Sila P4 上，有参考帧的 ROM 和必过的 PPU ROM 在两个后端上通过，结果一致，回退清单为空或者已经和用户确认。和参考帧不一致、确认是参考帧有错的 ROM，列出依据交给用户。
- PC 的 debug 构建和 `sila_p4-test-release` 构建通过，没有新的警告。
