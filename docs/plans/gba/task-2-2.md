# 任务 2-2：中断、定时器、DMA 和按键

在 2-1 的整机框架上加入中断、HALT 和 STOP、4 个定时器、4 个 DMA 通道、按键、没有对端的串口，以及 Direct Sound 的 FIFO 和 FIFO DMA 请求，两个后端同时实现。alyosha 和 nba-hw-test 的大部分用例从这里开始具备执行条件。这个任务依赖 2-1。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 路线图 GBA 段里程碑 2，[架构](../../architecture.md)的“时间线和事件”和“SM83 JIT”中的事件、推迟派发和成批运行。
- `refs/docs/gbatek.htm` 的 “GBA Interrupt Control”“GBA Timers”“GBA DMA Transfers”“GBA Keypad Input”“GBA Communication Ports”“GBA System Control”（HALTCNT）、“BIOS Halt Functions” 和 “GBA Sound Channel A and B - DMA Sound”。
- 1-1 的“用例选择”中这些模块的 alyosha 和 nba-hw-test 用例，以及它们的源码。

## 范围

- 中断：IE、IF 和 IME，IRQ 异常的进入。CPU 照常执行 BIOS 的 IRQ 入口代码，再跳到用户的中断处理程序。中断请求到 CPU 响应之间的延迟按 nba-hw-test `irq/irq-delay` 和 alyosha `irq` 的用例实现。
- HALTCNT 的 HALT 和 STOP，以及 BIOS 的 Halt、IntrWait 和 VBlankIntrWait 这些 SWI。BIOS 的代码由 CPU 执行，模拟器不另外实现这些调用。HALT 时直接推进到下一个设备事件，两个后端共用这段代码，不算作解释器回退。
- 4 个定时器的分频、级联、重载、启动和停止的时刻，以及溢出中断（nba-hw-test `timer`、alyosha `timer`）。定时器只在溢出和重载时安排事件，读中间值时按经过的时间计算。
- 4 个 DMA 通道：立即、VBlank、HBlank 和特殊启动，重复、地址的增减和固定、字和半字传输、各通道的地址范围，以及优先级和打断。启动延迟、寄存器的锁存、突发传输、强制 N 访问和从 BIOS 区读到的值，按 nba-hw-test `dma`、alyosha `DMA`、`Bus` 和 `timing` 的用例实现。DMA 和 CPU 争用总线时，CPU 停下的时间计入模拟时间。HBlank 和 VBlank 的启动时刻由 2-1 的 PPU 时序给出。
- 按 GBATEK “GBA DMA Transfers”，传输期间 CPU 停住，直到这次传输完成；声音和 HBlank、VBlank 的 DMA 每次触发只传一批，之后暂停，等下一次触发，暂停期间 CPU 照常运行。所以一次传输在启动它的那次访问或者那个事件里做完，传输中途到期的事件和更高优先级的通道也在里面处理，指令边界上不会有传到一半的传输。启动延迟还没过的通道，以及启用了重复、等待下一次触发的通道，它们的内部地址、剩余计数和锁存的寄存器是机器状态的一部分，状态的组织要让 4-1 能完整取出和恢复。一次很长的传输可以越过运行的目标时刻，和一条跨过目标时刻的指令一样处理。
- 按键：KEYINPUT 和 KEYCNT 的按键中断，按键由 CPU 的拥有者在指令边界提交。
- 串口只实现内部时钟、没有对端的传输，传输的时长和完成中断按 alyosha `Serial` 的用例实现。
- Direct Sound 的 FIFO A 和 B：写入、定时器溢出时出队、FIFO 剩下一半时向 DMA1 和 DMA2 发出请求，以及 SOUNDCNT_H 的复位位（alyosha `fifo_dma`）。出队的样本在这里只保留到 2-1 定下的接口里，声道合成和混音在里程碑 5。
- JIT：事件和可以响应的中断让块在指令边界退出。DMA 让 CPU 停下的时间在触发它的那次访问里过去。写 IE、IF、IME 和 HALTCNT 以后，块在指令边界退出。是否推迟派发只改变 IO 读出值的事件，由你按实测决定，推迟时程序不能观察到差别。
- 测试索引中这些模块的 ROM 改为具备执行条件，包括 1-2 自写的 32MiB ROM 的 DMA 读取测试。

## 不做

- PPU 的画面渲染，这在 2-3。
- 卡带存档芯片，这在 2-4。EEPROM 要用 DMA3，2-4 在这个任务的 DMA 上实现。
- 声道合成、混音和音频输出，这些在里程碑 5。
- 串口的外部时钟和联机。

## 约束

- 写代码时就要注意性能，解释器和 JIT 都一样。在满足功能的前提下选性能最好的实现，不写明显低效的代码，也不留给以后的优化任务再改。
- 设备仍然在被访问或者事件到期时才追赶到当前时刻，不逐周期推进。调度器的事件槽只按实际的设备数设置。
- 每条指令、每次访存的路径上不为这些设备增加检查。
- 判断为用例本身有错时，列出用例名和依据，和用户确认，不为了通过去迁就它。
- 改动共用的调度器或 JIT 后端时，GB 和 GBC 的结果不能变。开发期间不运行 GB 和 GBC 的测试，在 2-6 收尾时检查。
- 开发期间只构建要刷进板子的测试固件和 PC 的 debug 版。做完一段开发才上板，只运行改动影响到的模块的 ROM，以及和它们有交互的用例。
- 回退、测试时间和回传大小沿用 2-1 的规则。

## 由你决定

中断、定时器和 DMA 在调度器中的实现方式，DMA 和 CPU 争用总线的计时方法，FIFO 样本的保存格式，以及 JIT 处理事件和推迟派发的方式。选择的理由写在代码注释里。
