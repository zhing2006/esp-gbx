# 任务 2-4：卡带存档芯片

实现 GBA 卡带上的 SRAM、Flash 和 EEPROM，以及存档类型的自动判断，两个后端同时实现。存档文件的写回在 3-1，卡带上的 RTC 在 5-2。这个任务依赖 2-2，因为 EEPROM 要用 DMA3 传输。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 路线图 GBA 段里程碑 2，[产品设计](../../product-design.md)的“卡带存档”和“GBA 存档类型识别”。
- `refs/docs/gbatek.htm` 的 “GBA Cart Backup IDs”“GBA Cart Backup SRAM/FRAM”“GBA Cart Backup EEPROM” 和 “GBA Cart Backup Flash ROM”。
- jsmolka `save` 的源码，以及 1-2 自写的 EEPROM 测试 ROM 和不带 ID 字符串的 SRAM、Flash 测试 ROM。
- [架构](../../architecture.md)“系统接口”一节中卡带存档的部分。

## 范围

- SRAM：32KiB，8 位数据总线，16 位和 32 位访问的读出值和写入按 GBATEK。
- Flash：64KiB 和 128KiB，进入和退出 ID 模式、读出厂商和设备 ID、整片擦除、扇区擦除、写一个字节，以及 128KiB 的 bank 切换。Atmel 设备的 128 字节扇区写入是否实现，按选定的 ID 决定。报告给游戏的厂商和设备 ID 从 GBATEK 列出的设备类型中选，选择的依据写在注释里。擦除和写入的忙碌时间按 GBATEK 和 jsmolka 的用例定。
- EEPROM：512B 和 8KiB，DMA3 传送的位流、6 位和 14 位地址、64 位的读写，以及写入以后的忙碌和就绪（GBATEK 给出的约 108368 个周期）。ROM 不超过 16MiB 时，EEPROM 在 D000000h 至 DFFFFFFh 都可以访问；ROM 是 32MiB 时只在 DFFFF00h 以上，按 GBATEK。
- 存档类型按产品设计“GBA 存档类型识别”一节判断：有 ID 字符串时按字符串判断；没有时按游戏第一次访问存档区的方式判断。EEPROM 的容量在运行时按游戏第一次发出的位流的地址位数判断；没有 `FLASH1M_V` 时 Flash 按 64KiB 处理。调用者给出已有的存档类型和容量时，以它为准，3-1 用它从存档文件里恢复类型。
- 系统接口：取出和写回存档数据，报告存档类型和容量，以及上次查询以来程序可能写过存档。做法和 GB 的卡带 RAM 相同，拥有者在帧边界查询。
- JIT：存档区的访问经过处理函数。Flash 和 EEPROM 有命令状态，不能直接读写宿主内存；SRAM 能否直接访问由你按实测决定，直接访问时也要让存档的写回知道可能写过。
- 测试索引中 jsmolka `save` 和 1-2 自写的存档测试改为具备执行条件。

## 不做

- 存档文件、写回和断电保护，这些在 3-1。
- 卡带上的 GPIO 和 RTC，这在 5-2。
- 手动指定存档类型，见路线图 GBA 段的“未尽之事”。

## 约束

- 写代码时就要注意性能，解释器和 JIT 都一样。在满足功能的前提下选性能最好的实现，不写明显低效的代码，也不留给以后的优化任务再改。
- 存档芯片的状态以后要进即时存档，命令进行到一半的状态也要能完整取出和恢复。
- 每次访存的路径上不为存档增加检查，判断只放在存档区的处理函数里。
- 开发期间只构建要刷进板子的测试固件和 PC 的 debug 版，只运行存档相关的 ROM。
- 回退、测试时间和回传大小沿用 2-1 的规则。
