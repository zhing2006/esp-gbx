# 任务 5-2：卡带 RTC

实现 GBA 卡带上的 GPIO 和 S-3511 RTC，两个后端同时实现，并把 RTC 接进卡带存档、即时存档和关机补算。这个任务依赖 4-1，可以和 5-1 同时做。

开工时在[任务状态](status.md)里把这个任务标为“进行中”。

## 先读

- 路线图 GBA 段里程碑 5，[产品设计](../../product-design.md)的“RTC”和“即时存档”。
- `refs/docs/gbatek.htm` 的 “GBA Cart I/O Port (GPIO)” 和 “GBA Cart Real-Time Clock (RTC)”，以及它引用的 “DS Real-Time Clock (RTC)”。
- [架构](../../architecture.md)中 MBC3 RTC、卡带存档和即时存档的部分，以及 1-2 自写的 RTC 测试 ROM。

## 范围

- GPIO：080000C4h 至 080000C9h 的数据、方向和控制寄存器。读使能打开以后，这几个地址读出 GPIO 的值；没有打开时仍然读出 ROM 的内容，按 GBATEK。
- S-3511：串行命令、控制寄存器、日期时间和时间的读写、复位、12 和 24 小时制、BCD，以及断电标志。GBATEK 写明 alarm 一类寄存器总是读出 FFh。每分钟中断和中断输出按 GBATEK 实现到哪一步由你决定，没有实现的部分写明。
- RTC 按模拟时间推进，秒以下的部分按模拟时间保存，模拟核心不读宿主时间。调用者通过系统接口取出、写回完整状态，或者加上一段经过的时间，做法和 MBC3 的 RTC 相同。
- 哪些游戏带 RTC，按 ROM 头的游戏代码登记在一份记录里，每一条写明来源。GBATEK 只列出了 Boktai、P-Letter 和 Rockman EXE 4.5，其他游戏要找到有出处的资料才能登记，没有出处的不登记。1-2 的 RTC 测试 ROM 用自己的游戏代码登记，来源写这个测试 ROM。
- 卡带存档的文件里加上 RTC 的状态和写入时板上 RTC 的时间。载入时如果两个时间都可信，而且没有倒退，就补算关机期间经过的时间；否则不补算，提示 CLOCK NOT SET。暂停期间经过的时间在恢复运行时补算。
- 即时存档加上 GPIO 和 RTC 的状态，格式升版本；读档时按存档文件里的板上时间补算，游戏时钟不会因为读档而倒退。
- JIT：GPIO 的地址在 ROM 区里。读使能打开以后，JIT 的 ROM 快速路径不能对这几个地址直接读 ROM。

## 不做

- 太阳能传感器、倾斜传感器、陀螺仪和振动等其他 GPIO 外设，见路线图 GBA 段的“未尽之事”。
- 手动指定游戏带不带 RTC。

## 约束

- 写代码时就要注意性能，解释器和 JIT 都一样。在满足功能的前提下选性能最好的实现，不写明显低效的代码，也不留给以后的优化任务再改。
- 改动卡带存档和即时存档的共用代码时，GB 和 GBC 的 RTC 和存档不能变。开发期间不运行 GB 和 GBC 的测试，在 5-3 收尾时检查。
- 每次访存的路径上不为 GPIO 增加检查，检查只放在已经要分支的地方，比如 GPIO 所在的那一页。
- 开发期间只构建要刷进板子的固件和 PC 的 debug 版，只运行 RTC 相关的 ROM。

## 由你决定

GPIO 和 RTC 的实现结构，以及游戏记录的格式。选择的理由写在代码注释里，每条游戏记录的来源写在记录旁边。

## 完成标准

- 在 Sila P4 上，1-2 自写的 RTC 测试在两个后端上通过，结果一致，回退清单为空或者已经和用户确认。测试中途即时存档、读档以后仍然通过，`--states` 加入这个 ROM。
- 带 RTC 的游戏关机以后重新启动、读档以后，游戏时钟按经过的时间补算，不会倒退；板上 RTC 不可信时显示 CLOCK NOT SET。用户提供的游戏中没有带 RTC 的时，如实说明，只用测试 ROM 检查。
- PC 的 debug 构建和 `sila_p4-release`、`sila_p4-test-release` 构建通过，没有新的警告。
